Keeps track of what memory is in use and what memory is free. It allocates free memory to a process when need and deallocates when it is no longer needed. IT decided which processes or parts of processes and data move in and out of memory, transferring between RAM and disk.

## Memory sharing
As a result of CPU scheduling, we can improve:
- the utilisation of the CPU
- the speed of the computer's response to its users.
- To realise this increase in performance we must be able to keep several processes in memory at once.

## Types of memory
Memory comes in many types:
- Cache memory/CPU cache (e.g. L1, L2, etc.)
- Main memory (RAM)
- Storage memory (non-volatile e.g. flash memory in USB memory)
- Virtual memory
The cache and main memory are referred to as primary storage. The cache primarily supports, and is managed by, the CPU. It is invisible to the operating system. It uses the same memory management approaches as main memory, therefore are going to focus on main memory. 

## Basic hardware
Each process has a separate memory space. A pair of base and limit registers define the logical address space. CPU must check every memory access generated in user mode to be sure it is between base and limit for that user.

Protection of memory is required to ensure correct operation. Separate per-process memory space protects the processes from each other.

## Logical/Physical Addressing
Memory is made up of many memory cells. A memory cell is an electronic circuit that stores one bit of information. A logical address by the CPU; also referred to as virtual address. A physical address is the address seen by the memory unit.

The memory management  unit is a hardware device that at run time maps virtual to physical address.

## Memory partitioning
Memory is a finite resource and as with the CPU, needs to be managed as to be used as efficiently as possible.

The main memory is usually split into two partitions:
- Kernel processes are usually held in one partition.
- User processes are held in another partition.
Each partition is contained in a single contiguous section of memory. 

## Memory protection
Relocation registers used to protect user processes from each other, and from changing operating system code and data.
- Base register contains value of smallest physical address.
- Limit register contains range of logical addresses - each logical address must be less than the limit register 
- MMU maps logical addresses dynamically.

## Contiguous Allocation
If reading memory, contiguous memory can be read in sequence and is read faster. To achieve this an effective memory allocation strategy is required based on blocks of available memory scattered throughout memory. When a process arrives it is allocated memory from a hole large enough to accommodate it.

Some strategies for allocating memory:
- First-fit: Allocate the first hole that is big enough
- Best-fit: Allocate the smallest hole that is big enough
	- Must search entire list, unless ordered by size.
	- Produces the smallest leftover hole.
- Worst fit - Allocates the largest hole but also produces the largest leftover hole.
# Fragmentation
External fragmentation is memory space that is able to satisfy a request but it is not contiguous. Internal fragmentation is memory that is allocated successfully but may be slightly larger than the requested amount of memory. This size difference is due to memory being stored blocks divisible by 2, 4, 8,16 etc. Therefore a request for 27 bytes of memory will be allocated to a 32-byte block leaving 5 bytes unused.

First fit analysis reveals that given N blocks allocated, 0.5N blocks lot due to fragmentation, so 1/3 may be unusable. External fragmentation can be reduced by compaction: shuffling memory contents to place all free memory together in one large block.

## Paging
Physical address space of a process can be noncontiguous; process is allocated physical memory whenever the latter is available. This avoids external fragmentation and avoids the problem of varying sized memory chunks.

Physical memory is divided into fixed-size blocks called frames. Typically the size is a power of 2, between 512 and 8192 bytes. Logical memory is divided into blocks of the same size called pages. To run a program of size n pages, we need to find n free frames and load the program. This process is called paging. A page table is set up to help manage the mapping of logical to physical addresses, using an address translation. However we can still have internal fragmentation.

## Address Translation Scheme
The logical memory address generated by the CPU is divided into: 
- Page number (p): used as an index into a page table which contains the base address of each page in physical memory
- Page offset (d): combined with base address to define the physical memory address that is sent to the memory unit.

## Implementation of Page Table
The hardware implementation of the page table cam be done in several ways. The page table is kept in main memory and a page-table base register PTBR point to the page table.
In this scheme every data/ instruction access requires to memory accesses (one for the page table and one for the data/instruction). The two memory access problem can be solved by the use of a special fast-lookup hardware cache called associative memory or translation look aside buffers.
![[Pasted image 20250519200652.png]]
When a logical address is generated by the CPU, the MMU first checks if its page number is present in the TLB. If the page number is found, its frame number is immediately available and is used to access memory. If the page number is not in the TLB, memory reference to the page table must be made. SO the frame number is obtained and we can use it to access memory then we add the page number and frame number to the TLB so that they will be found quickly on the next reference. If the TLB is already full of entries, existing entry must be selected for replacement.

## Effective Access Time (EAT)
Hit ratio = $\alpha$ 
Hit ratio is the percentage of times that a page number is found in the associative registers; ratio related to number of associative registers.

EAT = (TLB hit-ratio x memory access time) + ((1 - TLB hit-ratio) x (2 x memory access time)). Consider $\alpha$ = 80%, 10ns for memory access, 10ns for page table search.
- EAT = 0.80 x 10 + 0.20 x 20 = 12ns
Consider $\alpha$ = 99%
- EAT = 0.99 x 10 + 0.01 x 20 = 10.1ns

Memory protection implemented by associating protection bit with each frame. A valid-invalid bit is attached to each entry in the page table:
- valid indicates that the associated page is in the process's logical address space and is thus a legal page.
- Invalid indicates that the page is not in the process's logical address space.
# Virtual Memory
Enables programs to address more memory than physically available in main memory. The logical address space is much larger than the physical address space, and pages are swapped (paged) in and out of main memory. Physical memory is shared among multiple processes.
The virtual address space includes:
- code (read only)
- data (read/write)
- heap(dynamic memory allocation during execution)
- stack (holds instructions and data for nested procedure calls)

# Demand Paging
Pages are loaded into memory only when required.
The benefits are that it reduces the number of pages transferred and frames allocated and it improves system response time and allows more processes to execute.
However, if a page is not in memory (invalid bit = 0), a page fault occurs.
Steps to handle this:
1. Check access validity.
2. If valid, find a free frame or replace a victim page.
3. Load the required page into memory.
4. Update the page table and restart the interrupted instruction.
The page fault rate (p) is the probability of a page fault ($0\leq p \leq 1$).
The effective access time = EAT = (1-p) x memory access + p x (page fault overhead + swap time)

## Page Replacement
Page replacement is required when no free frames are available.
Steps:
- Locate the desired page on disk.
- Select a victim page using a replacement algorithm
- Swap out the victim page and update tables.
- Load the desired page and restart the process.

### Page Replacement Algorithms
FIFO: Replaces the oldest page. Page faults may increase with more frames.
Optimal Algorithm: Replaces the page that will not be used for the longest time. Uses a theoretical benchmark, but is impractical due to requiring future knowledge.
Least Recently Used (LRU): Replaces the least recently accessed page. Can be implemented with a counter or a stack.

### Frame Allocation
 - Global replacement: frames can be taken from any process. 
 - Local replacement: frame are allocated per process.
 - Allocation methods:
	 - Fixed allocation: equal or proportional to process size
	 - Priority allocation: Higher-priority processes take frames from lower priority ones.
## Thrashing
Occurs when excessive paging reduces CPU utilization.
Causes: Insufficient frames leading to high page-fault rates.
Solutions:
- Prepaging: load all required pages before execution
- Page-fault frequency scheme: adjust frame allocation dynamically to maintain an acceptable fault rate. If they page fault rate of a certain process is above a high threshold the process is given more memory (page frames) to reduce the frequency of page faults. If it goes below a low threshold, it is given less memory, at the risk of more faults.
